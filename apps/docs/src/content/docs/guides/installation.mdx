## Add the dependency

Brew ships as `org.konaframework:kona-brew`. Add it next to your other Kona dependencies:

```kotlin
dependencies {
    implementation("org.konaframework:kona-http:0.1.0-SNAPSHOT")
    implementation("org.konaframework:kona-session:0.1.0-SNAPSHOT")
    implementation("org.konaframework:kona-crema:0.1.0-SNAPSHOT")
    implementation("org.konaframework:kona-brew:0.1.0-SNAPSHOT")
}
```

Until Central publishes are live, publish both repos to Maven local:

```bash
# From a Kona checkout
./gradlew publishToMavenLocal -x test

# From a kona-brew checkout
./gradlew :kona-brew:publishToMavenLocal
```

Or scaffold with the brew starter kit (when available on your Kona CLI):

```bash
kona new my-app --kit=brew
```

## Register the provider

Register HTTP, session, Crema, and Brew. Session + CSRF matter because update requests carry `_token`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Kona.create(args)
    .configure {
        it.set("app.key", Env.getOrDefault("APP_KEY", "change-me"))
        it.set("session.driver", "cookie")
    }
    .providers(
        HttpServiceProvider(),
        SessionServiceProvider(),
        CremaServiceProvider(),
        BrewServiceProvider(),
    )
    .afterBoot { app ->
        HttpMiddleware()
            .alias("start.session") { StartSession(app.resolve(SessionManager::class.java)) }
            .alias("csrf") { VerifyCsrfToken() }
            .web(listOf("start.session", "csrf"))
            .apply(app)
    }
    .boot()
```

</TabItem>
<TabItem label="Java">

```java
Kona.create(args)
    .configure(c -> {
        c.set("app.key", Env.getOrDefault("APP_KEY", "change-me"));
        c.set("session.driver", "cookie");
    })
    .providers(
        new HttpServiceProvider(),
        new SessionServiceProvider(),
        new CremaServiceProvider(),
        new BrewServiceProvider()
    )
    .afterBoot(app -> {
        new HttpMiddleware()
            .alias("start.session", () -> new StartSession(app.resolve(SessionManager.class)))
            .alias("csrf", VerifyCsrfToken::new)
            .web(List.of("start.session", "csrf"))
            .apply(app);
    })
    .boot();
```

</TabItem>
</Tabs>

`BrewServiceProvider` binds `BrewManager`, discovers components under `app.brew` by default, and registers:

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/brew/update` | Apply property updates + action calls; return new snapshots and HTML |
| `GET` | `/brew/brew.js` | Readable client bundle |
| `GET` | `/brew/brew.min.js` | Minified bundle (+ `.map`) |
| `GET` | `/brew/brew.csp.min.js` | CSP-oriented bundle when configured |

When `brew.inject_assets` is true (default), Brew injects styles and the script tag into full HTML responses that do not already include `@brewScripts`.

## Assets in layouts

For layouts you control explicitly:

```crema
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <title>@yield('title', 'App')</title>
    @brewStyles
</head>
<body>
    @yield('content')
    @brewScripts
</body>
</html>
```

`@brewScripts` emits the CSRF-aware script tag that loads Alpine + Brew and calls `Brew.start()` on `DOMContentLoaded` (unless you set `window.brewScriptConfig` for a custom ESM bundle).

## grind commands

After Brew is registered, app-local grind picks up Brew commands:

```bash
./grind make:brew counter
./grind make:brew todos --class
./grind make:brew counter --lang=java --test
./grind brew:publish
./grind brew:stubs
./grind brew:layout
./grind brew:convert path/to/Component.kt
```

See [grind commands](/dx/grind/) for details.

## Config keys

| Key | Default | Role |
|-----|---------|------|
| `app.key` | — | HMAC key for snapshot checksums |
| `brew.class_namespace` | `app.brew` | Package roots for `<brew:name />` resolution |
| `brew.path` | `/brew` | Base path for update + script routes |
| `brew.view_prefix` | `brew` | Convention view prefix (`views/brew/<name>.crema.html`) |
| `brew.inject_assets` | `true` | Auto-inject styles/scripts into HTML responses |
| `brew.inject_morph_markers` | `true` | Wrap loops/conditionals for keyed morph |
| `brew.csrf` | `true` | Require CSRF token on updates when a session exists |
| `brew.payload.max_size` | `1_048_576` | Max request body bytes (`0` disables) |
| `brew.payload.max_components` | `20` | Max components per update |
| `brew.payload.max_calls` | `50` | Max method calls per component |
| `brew.payload.max_nesting_depth` | `10` | Max dot-path depth for `wire:model` updates |

Custom routes:

```kotlin
Brew.setUpdateRoute("/custom/brew/update")
Brew.setScriptRoute("/custom/brew/script.js")
```

## Verify the install

1. Create a counter with `./grind make:brew counter`.
2. Embed `<brew:counter />` in a Crema page.
3. Open the page, click the button, and confirm the count updates without a full reload.
4. In DevTools, confirm `window.Brew` and `window.Alpine` exist.
